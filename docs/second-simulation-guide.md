# Коротка інструкція другої симуляції

Усі команди виконуються з кореня репозиторію. Основні результати: `results/conditions_contract_ml_2026_11_07/`. Постановка — партія 10 000 т, постійний склад техніки, не менше 4000 т за кожну повну добу від початку. Останній неповний період завершує залишок.

## 1 Переглянути результат

На [демонстраційному сайті](https://serbakh.github.io/transport-terminal-demo/) виберіть «Партія 10 000 т» і «Підбір техніки». Задайте ресурси та зовнішні умови. Порівняйте прогноз тривалості, добового обсягу, витрат і виконання норми. Рекомендація обирається серед допущених моделлю варіантів за тих самих зовнішніх умов.

У вкладці «Витрати та ставки» можна змінити ціни, після чого повернутися до підбору. Калькуляція й рекомендація перераховуються без навчання. Відтворення показує лише підготовлені записи, а не нові запуски симуляції.

## 2 Підготувати середовище

Python 3.12, PowerShell:

```powershell
py -3.12 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
```

Для перевірки таблиць і роботи зі збереженими моделями:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-ml.txt
```

Зафіксоване середовище завершеної серії: Python 3.12.14, SimPy 4.1.1, NumPy 2.3.1, pandas 2.3.1, scikit-learn 1.9.0. Файли `.joblib` потребують сумісного середовища; версії не оновлюються автоматично.

## 3 Отримати готовий прогноз і перерахувати ставки

```powershell
.\.venv\Scripts\python.exe tools/query_saved_results.py --trucks 11 --loaders 2 --unload-points 2 --external 0 --road 0
```

Команда читає збережену таблицю, показує вибраний склад і рекомендацію. Вона не завантажує `.joblib`, не запускає ML чи симуляцію та не інтерполює нові умови. Сітка: 4–20 автомобілів, 1–3 мехлопати, 1–3 комплекти, вагова 0/5/50%, дорожня надбавка до 0/5/15/30%.

Для зміни цін збережіть копію `examples/rates_uah.json` під власною назвою, відредагуйте потрібні ставки та передайте її шлях:

```powershell
.\.venv\Scripts\python.exe tools/query_saved_results.py --rates outputs/local/my_rates.json
```

Витрати перераховуються за збереженими фізичними прогнозами. Оригінальні таблиці, моделі та ставки експерименту залишаються незмінними.

## 4 Виконати один новий прогін

Перегляд плану без виконання:

```powershell
.\.venv\Scripts\python.exe -m src.dissertation_model --scenario examples/current_10000_11_2_2.json --daily-min-tons 4000
```

Один прогін за нульових зовнішніх впливів:

```powershell
.\.venv\Scripts\python.exe -m src.dissertation_model --scenario examples/current_10000_11_2_2.json --daily-min-tons 4000 --execute --output outputs/local/current_example
```

Для кожного запуску потрібен новий каталог. У результаті будуть `result.json` і `manifest.json`. У прикладі 11 автомобілів, 2 мехлопати, 2 комплекти, seed 10000. Очікувані підсумки за незмінного коду — близько 48,13 год і 570 258,32 грн. Це одиничний запис; середні п'яти контрольних прогонів — близько 48,18 год і 570 889,28 грн.

Умови задаються через `--conditions`, ставки — через `--rates`. Формати наведено в `examples/conditions.json` і `examples/rates_uah.json`. Дорожній відсоток — верхня межа випадкової надбавки, а не постійне подовження кожного рейсу.

## 5 Перевірити комплект

```powershell
.\.venv\Scripts\python.exe tools/run_tests.py
.\.venv\Scripts\python.exe tools/verify_conditions_study.py --output results/conditions_contract_ml_2026_11_07
```

Перевіряються контрольні суми коду й результатів, незмінність вихідної моделі, 27 540 прогонів, поділ seed, добова норма, калькуляція та економічний вибір. Друга команда оновлює тільки службовий `verification.json`; моделі й числові таблиці не переписуються.

## 6 Повторити весь експеримент за потреби

```powershell
.\.venv\Scripts\python.exe -m src.conditions_contract_study
.\.venv\Scripts\python.exe -m src.conditions_contract_study --execute --output outputs/local/new_conditions_study --workers 6
```

Перша команда лише показує план. Друга виконує всю серію та навчання; для читання готових результатів вона не потрібна. Завершений каталог захищений від перезапису. `--train-existing` призначений лише для відновлення незавершеної генерації, у якій ще немає `evaluation.json`.

`heldout_model.joblib` належить перевірці на відкладених складах; `final_model.joblib` — остаточному навчанню. Метрики подані окремо в `evaluation.json`.

## Межі застосування

Норма перевіряється за кожну повну добу. П'ять успішних контрольних повторів не гарантують майбутнього виконання. Враховані витрати не є підтвердженою повною собівартістю, прибутком або окупністю ML. Перед виробничим застосуванням потрібні перевірка ставок, наявності техніки й відповідності моделі реальному процесу.
